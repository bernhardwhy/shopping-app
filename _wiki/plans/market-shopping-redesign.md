# Introduction

Implement the approved design in two reviewable deliveries: **B**, a visual refresh that preserves existing shopping behavior, followed by a review gate, then **C**, a complete market feature over the existing `/groceries` collection. The engineer approved the design and O1-O3 resolutions on 2026-11-17. Before Phase 0, commit this plan and its matching objection record. No application changes have started.

## 1. Requirements & Constraints

- **REQ-001**: Deliver B first: refresh the existing shell, checklist, category sections, full-screen search dialog, and feedback states while preserving add, re-add, buy, name/category editing, loading, retry, and empty-list behavior. Maps to **AC-01, AC-06, AC-07, AC-08**.
- **REQ-002**: Stop after B for review. Do not start C tests or code until B is reviewed and accepted. C is one end-to-end delivery, not a filter-only release. Maps to **Delivery split and review gates; AC-05, AC-08**.
- **REQ-003**: C adds the fixed filters in order **Alle, Ohne Markt, Hofer, Billa, Lidl, Bauhaus**, outstanding counts including zero, and one-market-per-item filtering from the subscribed collection. Start each load at Alle; keep selection local. Maps to **AC-02, AC-03**.
- **REQ-004**: C uses stable IDs `hofer`, `billa`, `lidl`, `bauhaus`; optional `marketId` missing/null means unassigned; unknown IDs remain visible under Ohne Markt and recoverable in edit mode; clear assignment by writing null. Do not persist a filter sentinel or migrate records. Maps to **AC-04**.
- **REQ-005**: Preserve `buyed`, category identifiers, one shared list, existing Firebase ownership in `src/App.tsx`, narrow record updates, and component callback data flow. Derived outstanding items and counts must be recomputed for every realtime snapshot, without stale state. Maps to **AC-03, AC-05**.
- **REQ-006**: Implement C add/edit/re-add destination rules together: opening from a market defaults to that market; Alle/Ohne Markt defaults unassigned; re-add preserves saved market unless the selector was deliberately changed; create requires trimmed nonblank text and remains available alongside matches; active matches are labeled already on list. Maps to **AC-05**.
- **REQ-007**: C write callbacks return promises. Until resolution, retain the affected item's pre-write purchase state and market membership for rendering and count contributions, even if a local value event reports the optimistic change. Do not announce success/completion or remove/move the row before acknowledgment. On rejection retain retryable item/input state and show actionable error. Continue processing unrelated realtime changes; never restore a saved whole-collection snapshot. Maps to **AC-05, AC-08; O1 accepted**.
- **REQ-008**: Completion remains global. A selected-market completion message names that market and does not imply the whole list is complete; preserve navigation. Maps to **AC-03, AC-08**.
- **REQ-009**: Unknown/missing categories render as Sonstiges; retain known category order by current identifiers and sort a copied array, never mutate props or subscribed collection. Maps to **AC-06**.
- **REQ-010**: Meet the specified responsive/accessibility behavior: at 320px only the horizontal filter strip may overflow, 390px and 1280px layouts remain usable, fixed action does not obscure content, 200% zoom remains readable, controls have visible focus and labels, count/completion is politely announced, selected filter is textually indicated, and reduced motion is respected. Verify visual dimensions manually in a browser. Maps to **AC-07, AC-08**.
- **REQ-011**: Update `_wiki/architecture.md` and `README.md` alongside the shipped behavior; retain the story as the product decision record. The implementation plan and matching objection record are temporary and are deleted when implementation is complete. Maps to **Delivery split and review gates**.
- **REQ-012**: In B, normalize null collection snapshots to an empty array; support the first-item transition without errors. In C, retain all six zero-count filters on an empty collection. Maps to **AC-02, AC-04, AC-08; O2 accepted**.
- **REQ-013**: In C, after an acknowledged market edit removes the focused row from the active view, focus the selected market's filter and politely announce its destination, including when that was the last row. If focus moved outside that row while pending, do not steal it. Failed writes leave the row available without movement feedback. Maps to **AC-05, AC-07, AC-08; O3 accepted**.
- **SEC-001**: Before release, verify deployed Firebase validation rules accept optional `marketId` values and null clearing. Rules are external; do not loosen access, use production data for tests, or add rules to this repository.
- **CON-001**: Use React 16, Material-UI 4, TypeScript 4.9, Firebase 8, Jest/CRA, and existing dependencies. No framework/dependency/tooling upgrade, Firebase migration, service layer, router, state library, or new application component.
- **CON-002**: No quantities, prices, multi-market membership, market management, independent store lists, or new offline-write guarantees. Do not perform blanket cleanup unrelated to this story.
- **GUD-001**: Verify tests with `node scripts\run_tests.js` and production compilation with `node scripts\run_build.js`. Tests must be added before the production edits in their respective delivery.
- **PAT-001**: Follow existing `ReactDOM.render`/unmount Jest tests, component fixtures and `jest.fn()` callbacks; use `act` and `Simulate` for interactions. Add a focused `SearchDialog` test because its behavior changes; do not add dependencies or a new test layer.
- **PAT-002**: Preserve styling conventions: `App.css`/`GroceryList.css` classes and `SearchDialog` MUI 4 `makeStyles`/`createStyles`. Use accessible selected buttons in a labeled filter navigation, not ARIA tabs unless tabpanel and keyboard-tab behavior are also implemented.
- **PAT-003**: Existing `App` owns `/groceries` subscription and narrow update/push callbacks; `GroceryList` is a class with inline `AreaNames`, global edit mode, and currently mutates props using `.sort`; `SearchDialog` is a hook function, searches the full collection, renders bought records, and currently shows success before write acknowledgment. The interface in `src/groceryType.tsx` currently requires `area` although legacy data may omit it. Test and account for these conditions; do not assume they are already fixed.

## 3. Alternatives

- **ALT-001**: Add a market service, router, state library, or dedicated market components. Rejected because the existing App subscription and callback ownership are sufficient, and the proposal explicitly preserves existing components and architecture.
- **ALT-002**: Persist market catalog/filter state or migrate existing Firebase records. Rejected because the fixed catalog belongs in source, missing/null values already mean unassigned, and the proposal requires no migration and local filter selection.
- **ALT-003**: Use ARIA tabs for filters. Rejected because the proposed strip is a set of filters, not tabpanel navigation; use labeled navigation with accessible selected buttons.
- **ALT-004**: Test visual tokens through exact CSS-value assertions or introduce a browser/visual-test framework. Rejected because analogous tests use Jest/ReactDOM component behavior, no such framework is configured, and dimensions/zoom are explicitly verified manually.
- **ALT-005**: Ship filters separately from market-aware add, edit, re-add, and failure handling. Rejected because users could silently create or move an item to an unintended market; C is one coherent end-to-end delivery.

## 7. Risks & Assumptions

- **RISK-001**: External Firebase rules may reject `marketId` or null writes. Do not release C until authorized rule compatibility is verified; do not change access rules in this repository.
- **RISK-002**: Existing records may omit `area`, `marketId`, or contain unknown categories/market IDs. Normalize only for rendering/grouping; do not rewrite or hide records.
- **RISK-003**: Local Firebase events can precede server acknowledgment. Apply the approved per-record pending purchase/market overlay, retain retryable state on rejection, reconcile rollback in either ordering, and never overwrite unrelated updates with a saved collection.
- **RISK-004**: Fixed bottom action and horizontally overflowing filters can hide content or keyboard focus at narrow widths/zoom. Verify the specified viewport widths, zoom, focus order, and content clearance manually.
- **RISK-005**: Existing completion feedback assumes the last visible item means the entire list is done. C must scope completion to the active market and maintain access to all filters.
- **ASSUMPTION-001**: Design and objection resolutions are approved; the engineer commits the plan and objection record before Phase 0. B review acceptance happens before Phase 3. External Firebase rule verification is required before C release, not before local mocked development.
- **ASSUMPTION-002**: Every grocery record belongs to exactly one assigned market or the unassigned group; unknown IDs are treated as unassigned for display while preserving the original field until an explicit user edit.
- **ASSUMPTION-003**: Market management, persistence of filter selection, migration, and new offline behavior remain out of scope.
